## 5. 残タスク: Firestoreインデックスのデプロイ

### なぜ必要か

キャッシュ検索で `.where()` + `.order_by()` を組み合わせるクエリを使用しており、Firestoreの複合インデックスが必須。インデックスがないとクエリがエラーになり、毎回Gemini APIで再生成するフォールバック動作になる。

### 手順

詳細は [`docs/firestore-index-deploy.md`](./firestore-index-deploy.md) を参照。

**CLIの場合:**
```bash
firebase login
firebase deploy --only firestore:indexes --project hackason-grab
```

**コンソールの場合:**
https://console.firebase.google.com/project/hackason-grab/firestore/indexes から手動作成。

### 作成するインデックス

| コレクションID | フィールド |
|---------------|-----------|
| `items` | `hairPattern` ASC → `createdAt` DESC |
| `recipes` | `foodName` ASC → `hairPattern` ASC → `createdAt` DESC |

### 必要な権限

Firebase管理者 or GCPプロジェクト編集者以上（`akitake630@gmail.com` では権限不足で403エラー）。

## 6. 理想形の動作仕様（インデックスデプロイ後）

### ユーザーの2つの状態

| 状態 | 条件 |
|------|------|
| A. 写真解析済み | AIカメラ（Feature 1）で頭髪を撮影・分析済み |
| B. 写真解析なし | AIカメラ未使用。サイドバー等から直接アクセス |

---

#### (5) 「他のレシピを見る」クリック

```
useCache: false でAPI呼び出し
  → 強制的にGemini再生成
  → 新しいレシピを表示
  → 新レシピがFirestoreに保存（次回はこちらが返る）
```

---

### 動作フロー図

```
ページアクセス
    │
    ▼
[useCache: true で /recommend 呼び出し]
    │
    ├── キャッシュあり → 即表示
    │
    └── キャッシュなし → Gemini生成（プログレスバー表示）
                │
                ▼
            結果表示
            ├── 解析済み → パターンカード表示
            └── 解析なし → AIカメラ誘導バナー表示

「レシピを見る」クリック
    │
    ▼
[useCache: true で /recipe 呼び出し]
    │
    ├── キャッシュあり → 即表示
    └── キャッシュなし → Gemini生成 → 表示 + 保存

「他のレシピを見る」クリック
    │
    ▼
[useCache: false で /recipe 呼び出し]
    └── 強制Gemini再生成 → 新レシピ表示 + 保存
```

## 7. Firestore データ構造

```
foodRequests/
  {uid}/
    items/           ← レコメンドキャッシュ
      {auto_id}/
        createdAt: Timestamp
        hairPattern: "M字" | null
        nutrients: [...]
        shoppingList: [...]
        patternInfo: { label, description, cause, strategy } | null
    recipes/         ← レシピキャッシュ
      {auto_id}/
        createdAt: Timestamp
        foodName: "納豆"
        hairPattern: "M字" | null
        recipes: [{ name, description, ingredients, benefit }]
```

## 8. API エンドポイント

### POST `/api/v1/food-sniper/recommend`

リクエスト:
```json
{
  "message": "",
  "hairPattern": "M字",
  "useCache": true
}
```

レスポンス:
```json
{
  "patternInfo": { "label": "M字型薄毛", "description": "...", "cause": "...", "strategy": "..." },
  "nutrients": [...],
  "shoppingList": [...],
  "hairPattern": "M字",
  "hasAnalysis": true
}
```

### POST `/api/v1/food-sniper/recipe`

リクエスト:
```json
{
  "foodName": "納豆",
  "hairPattern": "M字",
  "useCache": true
}
```

`useCache: false` → 強制再生成（「他のレシピを見る」ボタン用）

レスポンス:
```json
{
  "recipes": [
    { "name": "納豆キムチ丼", "description": "...", "ingredients": ["納豆", "キムチ"], "benefit": "..." }
  ]
}
```

## 10. インデックス未デプロイ時の挙動

インデックスがなくても **機能は壊れない**。

| 機能 | インデックスあり | インデックスなし |
|------|----------------|----------------|
| レコメンド初回 | Gemini生成 + 保存 | Gemini生成 + 保存（同じ） |
| レコメンド2回目 | キャッシュから即表示 | Gemini再生成（毎回） |
| レシピ初回 | Gemini生成 + 保存 | Gemini生成 + 保存（同じ） |
| レシピ2回目 | キャッシュから即表示 | Gemini再生成（毎回） |
| 「他のレシピを見る」 | Gemini再生成 | Gemini再生成（同じ） |

フォールバックは `try/except` で実装済み。エラーログは Cloud Run のログに `WARNING` レベルで出力される。

## 11. 確認方法

インデックスデプロイ後の動作確認手順:

1. 食材レコメンドページにアクセス → プログレスバー表示 → 結果表示
2. **同じページを再度開く → ローディングなし/一瞬で即表示されれば成功**
3. 食材の「レシピを見る」→ レシピ生成 → モーダル表示
4. モーダルを閉じて **同じ食材の「レシピを見る」を再クリック → 即表示されれば成功**
5. 「他のレシピを見る」→ ローディング → 新しいレシピ表示
6. モーダルを閉じて再度「レシピを見る」→ Step 5 の新レシピが表示されれば成功
