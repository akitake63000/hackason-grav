**ホーム画面仕様（現状実装）**

- パス: `/home`
- 表示データ
  - 表示名: Firebase Authの`displayName`を優先し、Firestoreの`users/{uid}`の`displayName`があれば上書き。末尾に「さん」を付与。
  - 継続日数: Firestoreの`users/{uid}`の`streakDays`。未設定時は`0`。
- 表示内容
  - 挨拶: クライアント時刻で時間帯判定（深夜/午前/午後/夜）し「おはようございます/こんにちは/こんばんは」を切替。
  - 継続メッセージ: `streakDays`に応じて6段階で文言を切替。
    - `streakDays <= 0`: 「今日から一緒に始めましょう」
    - `1 <= streakDays < 3`: 「いいスタートです。少しずつ続けましょう」
    - `3 <= streakDays < 7`: 「いいペースです。無理なく続けましょう」
    - `7 <= streakDays < 14`: 「素晴らしい！継続は力なりです」
    - `14 <= streakDays < 30`: 「継続できています。あと少しで習慣化！」
    - `streakDays >= 30`: 「習慣化達成！この調子で続けましょう」
  - 機能メニュー: 3カード（AIチェック/チャット/生活アドバイザー）から `/feature1/capture`・`/feature2/chat`・`/feature3/tendency` へ遷移。
  - 今日のヒント: `/api/v1/lifestyle/tip`（Firebase ID Token必須 / `X-Firebase-Auth`）から取得。失敗時は固定のフォールバック文言を表示。
- 依存API
  - `/api/v1/lifestyle/tip`: 日本時間（Asia/Tokyo）の季節/時間帯に合わせた1文ヒント。Gemini無効時は季節別フォールバック。

### 5.2.x チームA 実装メモ（実装済み）

- 認証
  - Firebase Auth の永続化は **セッション**（ブラウザ終了でログアウト）

  - オンボーディングはプロフィール画面を再利用
  - 既存プロフィールを読み込んでフォームに反映
- 設定画面
  - `/settings/delete` を新設（削除対象の選択が可能）
  - 「退会」は **Firestore/Storage 全削除 + Firebase Auth アカウント削除**
  - 退会時に `auth/requires-recent-login` が出る場合は再ログイン案内
- 追加ページ
  - `/privacy` プライバシーポリシー
  - `/help` ヘルプ/FAQ
  - `/terms` 利用規約
- Gemini ヒント
  - 乱数の出力混入は除去（sanitize）

## 8.x 共通API/認証の使い方（チームA提供）

### 8.x.1 認証フロー（初回/2回目以降）

- 初回ログイン: Firebase Auth → `users/{uid}/profile/default` が未作成 → `/onboarding`
- 2回目以降: プロフィール存在 → `/home`

### 8.x.2 API 呼び出し（Firebase ID Token 自動付与）

共通ユーティリティ `apps/web/src/lib/api.ts` を利用する。

```ts
import { apiFetch } from "@/lib/api";

// 例: 画像解析
const res = await apiFetch("/api/v1/photos/analyze", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(payload),
});
```
※ Cloud Run を認証必須にする場合、`Authorization` は Cloud Run 用に使われるため、  
  Firebase ID Token は `X-Firebase-Auth` ヘッダで渡す。

### 8.x.3 401/未ログイン時の挙動

- `Layout` が未認証の場合 `/login` へリダイレクト  
- プロフィール未登録の場合 `/onboarding` へ誘導  

### 8.x.4 Cloud Run 認証ポリシー（本番）

- **本番は認証必須**（`ALLOW_UNAUTHENTICATED=false`）  
- Cloud Run の `allUsers` / `allAuthenticatedUsers` に `roles/run.invoker` を付与しない  
- 未認証アクセスは **401/403** になる想定  
- Firebase Hosting から Cloud Run を呼ぶ場合、Hosting のサービスアカウントに `roles/run.invoker` が必要  
- その場合ブラウザの `Authorization` は使えないため、Firebase ID Token は `X-Firebase-Auth` に付与する

### 8.x.5 一時対応（Hostingサービスエージェント未作成時）

- Firebase Hosting のサービスエージェントが作成できない間は、**一時的に** `ALLOW_UNAUTHENTICATED=true` とする  
- ただし **アプリ側では引き続き Firebase ID Token を必須**にする（`get_current_uid` で保護）  
- 目的: Hosting → Cloud Run 経由の CORS/403 を回避しつつ、APIは認証必須のまま運用
