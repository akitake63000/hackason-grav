# Daily Scheduler Cloud Function

毎日午前4時（JST）に実行される Cloud Function です。以下の処理を自動実行します：

1. **前日のログ自動確定**: 全ユーザーの前日ログに `isConfirmed: true` を設定
2. **当日のアクション自動生成**: 全ユーザーの当日ミッションを自動生成

## ディレクトリ構造

```
daily-scheduler/
├── main.py                    # Cloud Function エントリーポイント
├── requirements.txt           # 依存パッケージ
├── .env.yaml                  # 環境変数
├── shared/                    # 既存コードの再利用
│   ├── __init__.py
│   ├── firebase_client.py     # Firebase 初期化
│   ├── generate_plan.py       # generate_daily_actions をコピー
│   └── recommend_actions.py   # ACTIONS_CATALOG をコピー
├── deploy.sh                  # デプロイスクリプト
├── setup-scheduler.sh         # Cloud Scheduler 設定
└── README.md                  # このファイル
```

## デプロイ手順

### 1. Cloud Function のデプロイ

```bash
cd cloud-functions/daily-scheduler
./deploy.sh
```

このスクリプトは以下を実行します：
- Cloud Function を `asia-northeast1` リージョンにデプロイ
- Python 3.12 ランタイムを使用
- メモリ: 512MB
- タイムアウト: 9分（最大）
- 環境変数: `.env.yaml` から自動設定

### 2. Cloud Scheduler の設定

```bash
./setup-scheduler.sh
```

このスクリプトは以下を実行します：
- Cloud Scheduler ジョブ `daily-scheduler-4am-jst` を作成
- スケジュール: `0 4 * * *` (毎日午前4時)
- タイムゾーン: `Asia/Tokyo`
- ターゲット: デプロイした Cloud Function

### 3. 手動テスト

```bash
# Cloud Scheduler ジョブを手動実行
gcloud scheduler jobs run daily-scheduler-4am-jst \
  --location=asia-northeast1 \
  --project=hackason-grab

# ログを確認
gcloud functions logs read daily-scheduler \
  --region=asia-northeast1 \
  --project=hackason-grab \
  --limit=50
```

## 処理内容

### 前日のログ自動確定

- Firestore: `users/{uid}/plans/{planId}/logs/{yesterday}`
- ログが存在する場合:
  - `isConfirmed: false` なら `true` に更新
  - `autoConfirmedAt` タイムスタンプを追加
- ログが存在しない場合:
  - 空のログを作成して `isConfirmed: true` を設定

### 当日のアクション自動生成

- Firestore: `users/{uid}/plans/{planId}/dailyActions/{today}`
- 処理フロー:
  1. ユーザーの `tendencyScores/latest` からスコアを取得
  2. アクティブなプランを検索
  3. プラン期間内で、`dailyActions` が未作成の場合のみ生成
  4. `generate_daily_actions()` で3つのアクションを生成
  5. Firestore に保存（`autoGenerated: true` フラグ付き）

## 環境変数

`.env.yaml` に設定済み：

```yaml
FIREBASE_PROJECT_ID: hackason-grab
GOOGLE_CLOUD_PROJECT: hackason-grab
FIREBASE_STORAGE_BUCKET: hackason-grab.firebasestorage.app
```

## エラーハンドリング

- **ユーザー単位で分離**: 1人のエラーが他のユーザーに影響しない
- **プラン単位で分離**: 1つのプランのエラーが他のプランに影響しない
- **詳細なログ出力**: 各処理の成功/失敗をログに記録
- **部分成功のレポート**: 一部失敗しても成功した件数を返却

## トラブルシューティング

### Cloud Function が失敗する場合

1. ログを確認:
   ```bash
   gcloud functions logs read daily-scheduler --region=asia-northeast1 --limit=100
   ```

2. Firestore 接続を確認:
   - 環境変数 `FIREBASE_PROJECT_ID` が正しいか
   - Cloud Function に Firestore アクセス権限があるか

3. 再デプロイ:
   ```bash
   ./deploy.sh
   ```

### Cloud Scheduler が実行されない場合

1. ジョブの状態を確認:
   ```bash
   gcloud scheduler jobs describe daily-scheduler-4am-jst --location=asia-northeast1
   ```

2. 手動実行でテスト:
   ```bash
   gcloud scheduler jobs run daily-scheduler-4am-jst --location=asia-northeast1
   ```

3. ジョブを再作成:
   ```bash
   ./setup-scheduler.sh
   ```

## ロールバック

```bash
# Cloud Scheduler を一時停止
gcloud scheduler jobs pause daily-scheduler-4am-jst \
  --location=asia-northeast1 \
  --project=hackason-grab

# 再開
gcloud scheduler jobs resume daily-scheduler-4am-jst \
  --location=asia-northeast1 \
  --project=hackason-grab
```
